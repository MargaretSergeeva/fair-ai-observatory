# Demo Guide

## Recommended sequence

### 1. Act 1 — Product Demo

Explain that the UI is a scripted synthetic scenario designed to demonstrate the intended product flow.

Walk through:

1. schema and protected-attribute discovery;
2. risk-tier classification;
3. metric and threshold selection;
4. human configuration approval;
5. simulated pipeline execution;
6. before/after mitigation results;
7. the scripted 27.6% boundary-sensitivity finding.

Key message: mitigation improves the scripted fairness metrics but costs three accuracy points, and the robustness problem remains open.

### 2. UCI Reference Run

Explain that this is separate from the synthetic story and is generated by executable Python against the public UCI dataset.

Highlight:

- accuracy `73.67%`;
- gender disparate impact `0.9977` — PASS;
- foreign-worker proxy disparate impact `0.7944` — FAIL;
- mitigation improves DIR to `0.8342`, but the parity gap remains `0.1530` — FAIL;
- accuracy after mitigation `72.33%`;
- decision-boundary flip rate `22.22%` — FAIL;
- OOD flagged rate `3.67%` — INFO.

Key message: the system must report the evidence it actually finds. Gender checks pass, other group-quality checks fail, mitigation is incomplete, and the robustness concern remains open.

### 3. Act 2 — Process View

Show the proposed governance layer:

- milestones;
- agent roles and authority boundaries;
- decision log;
- stakeholder panel.

Key message: agents surface evidence and trade-offs; a human makes the decision.

### 4. Pipeline Schema

Close with the target architecture and explicitly distinguish it from the currently implemented reference path.

## Correct positioning

Use:

> This is an interactive concept prototype with a reproducible technical reference run.

Avoid:

- “production-ready compliance platform”;
- “automatically certifies EU AI Act compliance”;
- “the UI processes an uploaded dataset”;
- “all displayed Act 1 metrics come from UCI German Credit.”

## Local launch

```bash
cd demo
npm ci
npm run dev
```

Production build check:

```bash
cd demo
npm run check
```

## Netlify deployment

The root `netlify.toml` is the repository source of truth for deployment:

- base directory: `demo`;
- build command: `npm run build`;
- publish directory: `demo/dist` (`dist` relative to the base);
- Node.js: version 22 from `demo/.nvmrc`.

No SPA fallback redirect is configured because the demo does not use URL-based client routing. Unknown paths must return `404` rather than silently serving `index.html`.
